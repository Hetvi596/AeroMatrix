# Requirement-by-requirement evidence

This is a completed training/evaluation implementation with explicit scientific limits. “Implemented” is not a claim that ML outperforms baselines or is production-ready.

| Requirement | Status | Actual evidence and limits |
|---|---|---|
| Audit the exact supplied CSV | Completed | `data/audit.json`: 1,820,868 rows, 13 station IDs, 14 pollutant labels, units, per-field null counts, date coverage, exact/key duplicate audit, per-target gaps and extrema. No coordinates or weather columns. Timezone and interval semantics are explicit assumptions. |
| Acquire genuine historical weather | Completed with limits | `data/weather_provenance.json`, `data/weather_cache/`, `data/weather.csv.gz`: 84,192 ERA5 hourly grid rows, 12 cached bulk requests, two coarse grids, seven weather variables. Public Open-Meteo ERA5 redistribution; direct CDS credentials not supplied. |
| Verify station geography | Partial coverage | `config/stations.json` and official coordinate-page evidence: five matched Pune stations. Eight supplied locations, including PCMC locations, lack verified coordinates here and are excluded from spatial experiments. No fabricated geocoding. |
| Train missing-sensor forecasts | Completed | Twelve trained joblib models. PM2.5/PM10 one-hour forecasts; losses 0/10/30/50/70%, three seeds. Random, 12-hour blocks and full-station losses for network experiments; random losses across unseen folds. `evaluation/loss_realization.json` gives actual achieved masking. |
| Hold out whole monitoring locations | Completed for five stations | Ten independent location-holdout artifacts, separately trained/selected/calibrated without the target station's pollution values. `evaluation/model_manifest.json`, fold metadata and saved prediction files. Smallest folds have few eligible targets; do not generalize to all Pune/PCMC. |
| Earlier training, later evaluation | Completed with publication caveat | `config/experiment.json` and model manifests: train before Oct 2024, selection Oct–Nov, calibration Dec–Jan, test Feb–Sep 2025. Horizon boundary purge. Original measurement publication times and exact historical weather vintages are absent, so operational latency performance is not established. |
| Spatial/weather/temporal features | Completed where valid | `src/features.py`; spatial donors, time features and weather ablation. ERA5 delayed 120 days to avoid treating retrospective weather as available in real time. Most models select no-weather; PM2.5 Katraj holdout selects delayed weather. Current meteorological forecast capability is not claimed. |
| Identical-case baseline comparison | Completed where mathematically possible | `evaluation/metrics.csv`: shared-three and shared-spatial cohorts, MAE/RMSE/R²/bias/counts/coverage. Persistence cannot validly exist at a wholly excluded station; that cohort has n=0, not invented history. IDW/ML compare identical unseen cases. Persistence wins normal short-horizon cases. |
| Uncertainty and reliability | Completed, conditional | Separate chronological calibration; empirical coverage/width in metrics. Minimum two donors, maximum ages/distances, missing-input handling and out-of-distribution flags. Severe loss abstains. Marginal 90% calibration is not a guaranteed case-level confidence percentage. |
| Uncertainty-driven intervention stability | Implemented; domain validation outstanding | `src/planning.py` and `evaluation/intervention_sensitivity.json`: real forecast interval drives feasible subset selection under baseline/effect/budget/action changes. Costs/effects in the demo are explicitly hypothetical. No validated intervention-response catalogue or final teammate planner was supplied; real policy stability is not established. |
| Four reproducible scenarios | Completed | `examples/A_normal.json`, `B_missing_readings.json`, `C_unseen_station.json`, `D_severe_loss.json`; regenerate with `demos.py`. Saved ML outputs checked against row-level evaluation predictions; truth is separate from inference inputs. |
| Leakage prevention and independent truth | Implemented and tested | Excluded-station mutation test, future/late-available input rejection, atmospheric-model input rejection, strict chronological splits, training-only imputer, donor masks and untouched target labels. Timestamp/publication assumptions remain documented. |
| Save reproducible artifacts and evidence | Completed | Models, preprocessing pipelines, schemas/config, data/weather provenance, source, prediction CSVs, metrics, tests, manifests, software versions, Windows scripts and integration guide included. |
| Independent portable inference | Verification evidence included | `verify_portable.py` starts an actual HTTP API from a copy containing only src/models/config. `evaluation/portable_http.json` records results; no raw CSV, weather cache or original project is needed for inference with supplied recent inputs. Full extracted-package tests are recorded in `evaluation/export_verification.json`. |
| Preserve website | Completed | All new work resides in the separate package. No AeroMatrix application code, existing models, navigation, themes or AeroSage files were modified. No frontend integration or deployment is claimed. |

Read `TRAINING_RESULTS.md` for actual training counts and baseline scores. Check test logs and export verification for executed checks; health alone is never used as inference evidence.
